# 다음 단계: 설치형 앱용 조회 전환 준비

2026-11-05. 계획이며 이 문서 작성으로 배포·빌드 제출을 승인하지 않는다.

1번 구현 완료: `REACT_APP_STAGING_SECURE_SCHEDULE_READS=true`와 `REACT_APP_SECURE_SCHEDULE_READS=false` 조합으로 Staging 조회만 전환한다. 둘 다 기본 OFF이며 기존 운영 플래그 ON은 종전처럼 양쪽 경로를 활성화한다. 전체 앱 테스트 35 suites/205 tests 통과. 빌드 검증 결과는 최신 NEXT_SESSION을 참조한다. 다음 작업은 2번 설치형 후보 준비다.

## 권장 진행 방향

1. **로컬에서 Staging 전용 스위치를 준비한다.** 현재 단일 secure-read 스위치는 운영 경로도 바꾸므로, 운영 대응 함수가 미배포인 상태에서 그대로 설치형 앱에 넣으면 일반 로그인이 실패한다. 기존 운영 스위치를 유지하되 Staging만 새 경로를 쓰는 별도 명시적 설정을 만들고 OFF/OFF, OFF/ON, ON/ON 동작을 테스트한다. 새 스위치 이름과 실제 구현은 작업 시 기록한다.
2. **설치형 검증 후보를 준비한다.** 앱 ID `dev.pages.blccalendar` 유지. 기존 미커밋 native 변경을 비교하고, 빌드 설정·버전·산출물·교체 영향을 검토한다. 실제 iOS 빌드는 macOS/기존 Codemagic 경로가 필요하므로 현재 Windows에서 완료했다고 주장하지 않는다. master 자동 배포로 테스트 빌드를 만들지 않는다. `docs/release-checklist.md`의 승인 조건을 따른다.
3. **명시적으로 승인된 테스트 배포 후 실제 앱을 검증한다.** Staging 로그인, 역할 전환, 기수 제한, 새로고침, 앱 백그라운드 복귀, 로그아웃/재로그인을 확인한다. 현재 PC·아이폰 Safari 통과를 반복 요청하지 않는다. Android 기기가 없다면 미검증으로 남긴다. 테스트 데이터 수정이나 푸시는 읽기 전용 테스트와 분리하고 승인 범위를 확인한다.
4. **운영 대응 함수를 먼저 추가하는 방안을 검토한다.** 기존 공개 읽기는 그대로 둔 채 새 함수만 추가하면 이전 앱 경로는 유지된다. 배포 전 공유 코드 인증의 한계, 접근량·남용 방지, 응답 크기와 native 지연을 검토한다. 운영 배포에는 별도 명시적 승인 필요.
5. **호환 앱과 TV 웹을 순서대로 배포한다.** 정상 로그인·새 조회 경로를 확인하고 구버전 사용 현황과 강제/권장 업데이트 방식을 결정한다. GitHub push, 앱 빌드/스토어 제출, 웹 배포는 각각 명시적 범위를 확인한다.
6. **마지막에 공개 읽기를 차단한다.** 최신 데이터 백업, 적용 대상 규칙 검토, 구버전 지원 종료/공지, 중단 시 대응 계획이 준비된 후 별도 승인을 받아 후보 규칙을 적용한다. 이미 배포된 구버전이 계속 공개 조회한다면 즉시 차단하지 않는다. 공개 규칙으로 되돌리는 것은 기밀성 노출을 다시 만드는 조치다.

## 별도 해결해야 할 것

- 공유 코드 기반 권한은 개인 신원/배정 기수 인증이 아니다. 기존 사용 편의를 유지하는 과도기와 개인/발급형 인증 설계는 분리해 설명한다. 코드 교체나 새 가입 절차를 임의로 도입하지 않는다.
- UCSD 조직 반출은 학교 회신과 지원팀 절차가 필요하다. 읽기 권한 개선 완료와 조직 독립 완료를 혼동하지 않는다.
- 학교 계정 제거는 조직·복구·배포 접근 등 전체 독립성 검증 후 마지막에 진행한다.
